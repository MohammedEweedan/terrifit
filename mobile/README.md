# Terrifit — native app

The iOS and Android app. Same account, same API and the same numbers as the web
app at `/[locale]/app`; scores are computed on the server so the two can never
disagree, and a change to a formula ships to both without an App Store review.

## Running it

```bash
npm install          # from this directory, once
npm run ios          # builds a development build and launches it
npm start            # afterwards, this is enough — it reuses the build
```

The Next.js app has to be running too:

```bash
cd .. && npm run dev
```

### Why a development build and not Expo Go

Expo Go on the App Store only runs projects on the SDK that particular binary
was compiled against, and Apple's review queue means it lags the SDK release by
days or weeks. On SDK 57 that shows up as:

> The project you requested requires a newer version of Expo Go.

Updating Expo Go does not fix it — the version you need has not shipped yet. A
development build sidesteps the whole problem: it is Expo Go with *this*
project's native runtime compiled in, built from `app.json` on your machine.
Build it once and `npm start` attaches to it from then on, with the same fast
refresh.

First build takes a few minutes (CocoaPods, then Xcode). After that it is
instant unless a native dependency changes.

```bash
npm run ios                   # simulator
npm run ios -- --device       # a plugged-in iPhone
npm run android
```

For a physical iPhone the CLI asks for an Apple ID the first time and signs with
a personal team. A free account works; the provisioning profile expires after
seven days, so rebuild when the app stops opening. A paid Apple Developer
account lifts that to a year.

`ios/` and `android/` are generated by `expo prebuild` and are gitignored —
`app.json` is the source of truth, so regenerate rather than edit them.

## Pointing it at a backend

By default the app talks to port 3000 on whichever host is serving Metro, which
is right for a simulator and for a phone on the same Wi-Fi. Override it for
anything else:

```bash
EXPO_PUBLIC_API_URL=https://terrifit.example npm start
```

## How it is put together

```
app/
  _layout.tsx        auth gate + Anton, the display face shared with the site
  sign-in.tsx        POSTs { client: "native" } so the server returns a token
  (tabs)/
    index.tsx        Today — readiness dial, the four scores
    trends.tsx       Trends — one metric at a time over 30 or 90 days
    body.tsx         Body — composition, deltas, every scan on file
src/
  api.ts             the only place that talks to the backend
  session.tsx        token in the device keychain, never AsyncStorage
  data.ts            fetch on mount + pull-to-refresh; a 401 signs you out
  theme.ts           the same tokens as the web app's `.ap-` block
  format.ts          durations, weights, dates
  components/        Dial, Sparkline, ScoreCard, Screen, TabIcon
```

`src/theme.ts` and the web app's `.ap-` custom properties are the same values
written twice. If a colour changes in one and not the other, that is a bug.

## When a build breaks

**`Failed to load 'hermes-engine' podspec: ... failed SHA verification`** — a
cached artifact in `~/Library/Caches/ReactNative` is complete but wrong, and
CocoaPods only re-downloads a file that is missing, so retrying hits the same
one forever. Delete it and the pod cache, then build again:

```bash
rm -f ~/Library/Caches/ReactNative/hermes-ios-*.tar.gz
rm -rf ~/Library/Caches/CocoaPods/Pods/External/hermes-engine
npm run ios
```

**`Failed to resolve plugin for module "x"`** — `app.json` lists a config plugin
whose package is not installed. `npx expo install x`, then rebuild.

**`ENOENT: assets/logo-pack`** — nothing to do with this project. It is Expo Go
on a phone still pointed at Metro, asking for its own bundled asset. Close it.

## Checks

```bash
npm run typecheck
npx expo export --platform ios   # proves the bundle builds
npx expo prebuild --clean        # regenerates ios/ and android/ from app.json
```
